    - 使用 useIssues(projectId, filters) 获取 Issue 数据（filters 从 useStore().issue.filters 读取，与列表视图共享 per D-P16-16 note）

    - 使用 useIssueMutations().updateIssue 处理拖拽后的状态变更

    - 分组逻辑（根据 IssueStore.groupBy）per D-P16-14：
      a) "state"（默认）：从 MOCK_STATES 获取项目所有状态，按状态分组，每列一个状态
      b) "priority"：按 urgent/high/medium/low/none 分组
      c) "assignees"：按 assignee_ids 分组，无负责人归入"未指派"

    - GroupBySelector：顶部下拉选择器，选项为 state/priority/assignees（中文标签：按状态/按优先级/按负责人）
      - 选择后调用 IssueStore.setGroupBy
      - 使用 lucide-react 的 Columns icon + Dropdown UI
      - 筛选条件显示：读取 IssueStore.filters，显示已激活的筛选 chip（与列表视图 QuickFilterBar 共享）

    - 渲染结构：
      a) GroupBySelector（在视图顶部）
      b) 容器 div（overflow-x-auto 水平滚动，flex flex-row gap-4）
      c) 根据分组方式将 Issues 分配到各组
      d) DragDropContext 包裹，onDragEnd 处理函数：
         - 从 result 中提取 draggableId（Issue ID）、destination（目标列 ID）
         - destination.droppableId = 目标状态/分组 ID
         - 调用 updateIssue.mutate({ issueId: draggableId, data: { state_id/priority/assignee_ids: destination.droppableId } })
         - 在 onMutate 中取消进行中的查询并乐观更新（per RESEARCH.md Pitfall 1 避免：先 cancelQueries，再手动 setQueryData）
         - 使用 useRef guard 防止 StrictMode 双重触发（Pitfall 5）

    - 加载状态：显示 5 列 Loader 骨架卡片
    - 空状态：显示 "暂无 Issue"
    - 使用 observer() 包裹
