实现多 Scheme 认证协商基础设施。根据 D-01 决策，JWT Bearer / API Key / Session Cookie 各注册一个 AuthenticationScheme，通过 PolicyScheme 作为 DefaultScheme 路由器，按请求 Header 自动选择合适的认证方案。

Purpose: 这是 Phase 1 认证体系的核心基础，后续所有认证端点（Plane 兼容 /auth/*、OAuth、API Token）都依赖此多 Scheme 基础设施。
Output: 3 个认证方案注册完毕，PolicyScheme 路由器配置完成，编译通过。
</objective>

    **ApiKeyAuthenticationOptions.cs:** 继承 `AuthenticationSchemeOptions`，添加 `HeaderName` 属性（默认值 `"X-Api-Key"`）。参照 `JwtOptions.cs` 的模式。

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → API Server | 所有认证 Header（JWT/API Key/Cookie）从不可信客户端传入 |
| ApiKeyAuthenticationHandler → IApiTokenService | Handler 通过 DI 获取 Service，不直接访问数据库 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Spoofing | API Key AuthenticationHandler | mitigate | Handler 通过 IApiTokenService.ValidateAndGetOwnerAsync 查数据库验证哈希值，不信任客户端传入的任何身份信息 |
| T-01-02 | Spoofing | Session Cookie | mitigate | ASP.NET Core Cookie Authentication 内置数据保护（DPAPI），Cookie 自动加密防篡改 |
| T-01-03 | Information Disclosure | PolicyScheme Selector | accept | Selector 仅读取 Header/Cookie 名称做路由决策，不暴露内部实现细节 |
| T-01-04 | Elevation of Privilege | Claims Construction | mitigate | API Key Handler 的 Claims 完全由数据库查询结果决定（UserId/Email/TenantId/Permissions），不接受客户端提供的 Claims |
| T-01-05 | Denial of Service | API Key per-request DB lookup | mitigate | Plan 04 将添加 Redis 缓存层（Pitfall 3），Phase 1 先用直接查询 + 后续优化 |
</threat_model>
