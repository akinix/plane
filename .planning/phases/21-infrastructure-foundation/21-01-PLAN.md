    创建 `src/lib/types/api-error.ts`，定义以下类型（严格 TypeScript 接口，不使用 `any`）：

    1. `ProblemDetails` — RFC 7807 格式（.NET 原生返回）：
       - `type?: string`
       - `title?: string`
       - `status?: number`
       - `detail?: string`
       - `instance?: string`
       - `traceId?: string`
       - `errors?: Record<string, string[]>`（FluentValidation 字段级错误）

    2. `PlaneError` — Plane 传统格式：
       - `error?: string`
       - `status?: number`

    3. `ApiFieldError` — 单个字段级错误：
       - `field: string`
       - `messages: string[]`

    4. `StandardizedApiError` — 前端统一消费格式：
       - `message: string` — 人类可读的错误消息
       - `statusCode?: number` — HTTP 状态码
       - `fieldErrors?: ApiFieldError[]` — 字段级验证错误列表
       - `originalType?: string` — 原始错误类型标识（`ProblemDetails` / `PlaneError` / `unknown`）

    5. 导出工具函数 `standardizeApiError(data: unknown): StandardizedApiError`
       - 检测 `data` 是否包含 `type`、`title`、`detail` 字段 → 视为 ProblemDetails
       - 检测是否包含 `error` 字符串字段 → 视为 PlaneError
       - FluentValidation 格式: `errors` 对象 `{ [fieldName]: string[] }` 映射到 `ApiFieldError[]`
       - 兜底: `message` 取 `data?.detail || data?.title || data?.error || JSON.stringify(data) || "未知错误"`
       - `statusCode` 从 `data.status` 取（HTTP 状态码）

       - **跳过 JSON 字符串请求体**：如果 `config.data` 是字符串类型（即已序列化），跳过处理
       - **嵌套对象支持**：标准 `humps.decamelizeKeys` 已递归处理嵌套；无需额外逻辑
       - **注意**：`config.transformRequest` 中设置自定义 transform 时，确保不覆盖 Axios 默认的 JSON 序列化行为（Axios 默认会 `JSON.stringify` 对象请求体）。推荐的实现方式是在默认的 `transformRequest` 数组头部插入 decamelize 步骤

       ```
       // 推荐的实现方式：
       this.axiosInstance.interceptors.request.use((config) => {
         // JWT 逻辑保持不变
         const token = getToken();
         if (token) {
           config.headers.Authorization = `Bearer ${token}`;
         }

         // INFRA-01: camelCase → snake_case 请求体转换
         if (config.data && typeof config.data === "object" && !(config.data instanceof FormData)) {
           config.data = humps.decamelizeKeys(config.data, { separator: "_" });
         }
         // 查询字符串参数也转换
         if (config.params && typeof config.params === "object") {
           config.params = humps.decamelizeKeys(config.params, { separator: "_" });
         }
         return config;
       });
       ```

    3. **注意**：
       - `humps.decamelizeKeys` 默认使用 `_` 分隔符，符合 snake_case 要求
       - `config.transformRequest` 不要覆盖——让 Axios 默认处理 JSON 序列化
       - 请求体是 `FormData`、`URLSearchParams` 或字符串时跳过转换

    更新 `flow-api.service.ts` 的响应拦截器——重写 `interceptors.response.use` 的 error 回调：

    **第一步：添加模块级 Token 刷新状态（在类定义之外）**
    ```
    // Token 刷新队列状态（INFRA-02）
    let isRefreshing = false;
    let failedQueue: Array<{
      resolve: (value?: unknown) => void;
      reject: (reason?: unknown) => void;
    }> = [];
    let refreshPromise: Promise<void> | null = null;

    // 刷新 Token 的函数注入点（避免 AuthService 循环依赖）
    let refreshHandler: (() => Promise<void>) | null = null;

    export function registerRefreshHandler(handler: () => Promise<void>): void {
      refreshHandler = handler;
    }

    function processQueue(error: unknown, token: string | null = null): void {
      failedQueue.forEach((prom) => {
        if (error) {
          prom.reject(error);
        } else {
          prom.resolve(token);
        }
      });
      failedQueue = [];
    }
    ```

    **第二步：在 AuthService 中注册刷新函数**
    在 `auth.service.ts` 中：
    - 导入 `registerRefreshHandler`：`import { registerRefreshHandler } from "./flow-api.service";`
    - 注册时机：在 `AuthService` 的构造函数中调用 `registerRefreshHandler(() => this.refreshToken().then(() => {}))`
    - 确保构造函数中的注册调用放在 `super()` 之后

    **第三步：重写响应拦截器的 error 回调**

    ```
    (error) => {
      const originalRequest = error.config;

      // INFRA-04: 错误标准化（先对任何可用的 response.data 做标准化）
      if (error?.response?.data) {
        error.response.data = standardizeApiError(error.response.data);
      }

      // INFRA-02: 401 Token 刷新队列
      if (error?.response?.status === 401 && !originalRequest._retry) {
        // 防止刷新端点自身的 401 导致无限循环
        if (originalRequest.url?.includes('/auth/refresh/')) {
          removeToken();
          window.location.href = "/auth/sign-in";
          return Promise.reject(error);
        }

        if (isRefreshing && refreshPromise) {
          // 已经在刷新中——排队等待
          return new Promise((resolve, reject) => {
            failedQueue.push({
              resolve: () => {
                originalRequest.headers.Authorization = `Bearer ${getToken()}`;
                resolve(this.axiosInstance(originalRequest));
              },
              reject,
            });
          }).then(() => Promise.reject(error));
        }

        // 开始刷新
        originalRequest._retry = true;
        isRefreshing = true;

        if (!refreshHandler) {
          // 无刷新处理器——理论不应发生（AuthService 会在启动时注册）
          removeToken();
          window.location.href = "/auth/sign-in";
          return Promise.reject(error);
        }

        refreshPromise = refreshHandler()
          .then(() => {
            isRefreshing = false;
            processQueue(null, getToken());
          })
          .catch((refreshError) => {
            isRefreshing = false;
            processQueue(refreshError, null);
            removeToken();
            window.location.href = "/auth/sign-in";
            return Promise.reject(refreshError);
          });

        return new Promise((resolve, reject) => {
          failedQueue.push({
            resolve: () => {
              originalRequest.headers.Authorization = `Bearer ${getToken()}`;
              resolve(this.axiosInstance(originalRequest));
            },
            reject,
          });
        });
      }

      return Promise.reject(error);
    }
    ```

    **实现细节：**
    - `refreshHandler` 是模块级变量，通过 `registerRefreshHandler()` 注入
    - `isRefreshing` 标志防止重复刷新
    - `failedQueue` 存储所有排队请求的 resolve/reject
    - `processQueue` 在刷新完成或失败后统一处理排队请求
    - `originalRequest._retry` 防止重试循环
    - `/auth/refresh/` 自身的 401 不触发刷新（直接登出）
    - 刷新成功后，排队请求自动用新 Token 重试
    - 刷新失败后，排队请求全部 reject，Token 清除，页面跳转登录
