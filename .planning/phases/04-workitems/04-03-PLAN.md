    **CreateIssue** — POST /work-items/:
    - Command: ICommand&lt;CreateIssueResponse&gt;. Fields: Name (string), DescriptionHtml (string?), DescriptionJson (string?), Priority (string default "none"), ParentId (Guid?), StateId (Guid? — null = auto-assign default), EstimatePointId (Guid?), StartDate (DateOnly?), TargetDate (DateOnly?), AssigneeIds (List&lt;string&gt;?), LabelIds (List&lt;Guid&gt;?), IsDraft (bool, default false). [JsonIgnore] ProjectId.
    - Endpoint: Populates ProjectId from route. RequiresWorkspaceRole(Admin, Member, Guest) per CONTEXT. Returns 201 with location.
    - Handler (CRITICAL):
      1. Resolves project's default state: if StateId not provided, query States table for project default (IsDefault=true). If no default, use first state ordered by SortOrder.
      2. Generates SequenceId via IssueSequenceService.GetNextSequenceIdAsync (transaction-safe).
      3. Creates Issue via Issue.Create(...). Sets SequenceId from service.
      4. If assigneeIds provided: creates IssueAssignee entries (full replacement pattern).
      5. If labelIds provided: creates IssueLabel entries (full replacement pattern).
      6. Saves via SaveChangesAsync. Returns response with Id + SequenceId.
      7. Per RESEARCH Pitfall 6 (cross-DbContext ProjectId validation): handler should do a lightweight check via ProjectDbContext to confirm projectId exists. Access ProjectDbContext via service injection.
    - Validator: Name required max 255. Priority must be one of 5 valid values. ParentId must not equal Id (self-reference guard). If ParentId provided, depth-1 check(no grandparent — but DB constraint at app layer). Dates: StartDate before TargetDate.

    **GetIssue** — GET /work-items/{issueId}/:
    - Query: IQuery&lt;IssueDetailDto&gt;. [JsonIgnore] ProjectId, IssueId.
    - Endpoint: Route params projectId, issueId. RequiresAuthorization.
    - Handler: AsNoTracking, Include(assignees).Include(labels). Maps to IssueDetailDto with resolved state name, sequence display ("PROJ-1"), and navigation collections.

    **UpdateIssue** — PATCH /work-items/{issueId}/:
    - Command: ICommand&lt;IssueDto&gt;. [JsonIgnore] ProjectId, IssueId. Mutable fields matching Issue.UpdateDetails and UpdateState: Name?, Priority?, DescriptionHtml?, DescriptionJson?, StateId (Guid?), EstimatePointId?, StartDate?, TargetDate?, IsDraft?, AssigneeIds (List&lt;string&gt;?), LabelIds (List&lt;Guid&gt;?).
    - Handler (CRITICAL — multiple responsibilities):
      1. Fetches Issue with state info (State.Group). Checks closed-state semantics per RESEARCH Pitfall 5: if current state is Completed or Cancelled group, reject update with 400 "Cannot edit closed issue. Reopen first." (Only allow state change to reopen.)
      2. If StateId changing: looks up new state's Group. If new group is Completed, calls issue.UpdateState(stateId, isCompletedGroup: true). If new group is Cancelled, calls issue.UpdateState(stateId, isCancelledGroup: true). Else calls issue.UpdateState(stateId). This triggers CompletedAt sync.
      3. Calls issue.UpdateDetails(...) for other mutable fields. Captures field changes via domain events.
      4. If assigneeIds provided: issue.UpdateAssigneeList(assigneeIds) full replacement within same SaveChanges.
      5. If labelIds provided: issue.UpdateLabelList(labelIds) full replacement within same SaveChanges.
      6. Saves. Returns DTO.
    - Validator: Same rules as CreateIssue validator for mutable fields.

    **DeleteIssue** — DELETE /work-items/{issueId}/:
    - Command: ICommand (void). [JsonIgnore] ProjectId, IssueId.
    - Endpoint: RequiresWorkspaceRole(Admin, Member).
    - Handler: Fetches Issue. SoftDelete. IssueConfiguration cascade handles IssueAssignee, IssueLabel cleanup. Saves. Returns 204.
    - Validator: issueId required.
